# SixFeat

Короче. Слушаешь трек, там фит, и думаешь — а эти двое когда успели? А если
между ними не один шаг, а четыре? Вот SixFeat про это.

Он берёт данные с Genius, строит граф — кто с кем реально записывался — и
показывает путь от одного артиста до другого. Кликаешь по узлу, он
раскрывается, граф растёт. Роли тоже видно: кто зафитовал, кто спродюсировал,
кто написал текст.

Ещё есть игра: соединить двух артистов за минимум шагов. Схитрить не выйдет,
цепочку проверяет сервер.

> **Потыкать негде.** Ни сайта, ни демки — нигде не крутится, кроме моего
> компа. Всё ниже про то, как поднять у себя.

## Статус: доделан, а не брошен

Разница есть. **Брошен** — это когда надоело и оставил как есть. **Доделан** —
это когда всё запланированное сделано, тикетов ноль, CI зелёный, и ты
останавливаешься сам.

Остановился 11 августа 2026.

Вернусь, если появится музыкальный сервис с нормальным API — популярным и не
золотым по цене. Условие такое из-за конкретной истории. Я взял вторым
источником данных Яндекс.Музыку и построил под неё половину проекта:
отдельный сервис, свой OAuth, импорт плейлистов, идентичность артистов
переделана под двух провайдеров. **Потом Яндекс закрыл API и отозвал
доступ.** Без предупреждения, за день. Не подорожал, не стал хуже работать —
просто перестал пускать.

Пять тысяч строк туда, пять тысяч обратно.

Дело не в том, что я выбрал не тот сервис. Дело в том, что доступ держался на
API, который никому ничего не обещал: ни договора, ни условий, ни уведомления
о закрытии. Так что теперь сначала условие, потом код.

Докручивать то, что уже работает на Genius, не буду — хватает.

## Как поднять

```bash
git config user.name "Имя" && git config user.email "почта@example.org"
make install-hooks
make deploy-local
```

Нужен Docker с compose и ключи Genius OAuth (`GENIUS_CLIENT_ID` и
`GENIUS_CLIENT_SECRET` берутся на https://genius.com/api-clients), плюс
`APP_SECRET` — это просто `openssl rand -hex 32`.

Если поднимать пока лень, а проверить, что конфиг сходится, хочется:
`make deploy-local-check` — прогоняет всё до подъёма стека и ничего не
запускает.

Что-то не поехало — в [docs/DEVELOPMENT.md](./docs/DEVELOPMENT.md) есть
раздел ровно про это, там же все переменные.

## Что внутри

Пять сервисов на C++ (фреймворк userver), под ними Postgres. Сначала всё было
одним куском; разъехалось потому, что у графа, у походов в Genius и у игры
разный профиль нагрузки и разный темп изменений. Почему именно так —
[ADR-0001](./docs/adr/0001-split-into-four-services.md) и
[ADR-0007](./docs/adr/0007-game-mode-as-separate-service.md).


| Сервис | Чем занят |
| --- | --- |
| `six-feat` | граф, пути, поиск, публичный API — через него всё и ходит |
| `six-feat-genius-gateway` | один за всех ходит в Genius: лимиты, кэш, предохранитель |
| `six-feat-auth` | вход через Genius |
| `six-feat-enrichment` | дособирает граф в фоне |
| `game` | игра: челленджи, очки, таблица лидеров |

Фронт — обычный JS, без React и прочего, граф рисуется на canvas. Где какой
узел стоит и как обвести группу — считает сервер, браузер только рисует. Так
вышло не столько быстрее, сколько честнее: раньше одно и то же считалось
дважды на двух языках, и эти двое иногда расходились во мнениях.

## Про тесты

Их много, и это специально. 31 джоба в CI.

Причина проверена на себе: однажды пришлось удалить из проекта пять тысяч
строк — целый источник данных со всеми следами. Такое делается спокойно
только когда есть чем проверить, что не задел лишнего.

Бэкенд проверяется питоном против живого сервиса (Genius при этом
подменяется моком). Чистые C++-библиотеки собираются в `.so` и дёргаются из
того же питона через `ctypes` — покрытие C++ под гейтом 80%. Фронт — vitest,
тоже 80%, плюс e2e в настоящем браузере.

Сверху ещё clang-tidy, clang-format, eslint, prettier, ruff и пачка своих
проверок: сходятся ли env-профили, сходится ли схема БД между C++ и `.sql`,
не завелись ли комментарии, которые никому не нужны.

Что померено по-настоящему — в [docs/benchmarks/](./docs/benchmarks/README.md),
вместе со списком того, до чего руки не дошли.
