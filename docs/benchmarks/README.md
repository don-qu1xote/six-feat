# Замеры

Что измерено и сколько получилось.

Нагрузочный харнесс на k6 (SF-INF-05) и бюджет размера бандла (SF-WEB-08)
завелись в проекте рано. Инструменты есть, записанных результатов почти нет:
гоняли и смотрели глазами. Здесь собрано то, что успели померить всерьёз.

Числа сняты на конкретной машине в конкретный день. На другом железе они
будут другими; смотреть стоит на порядок величин и на сравнения внутри
одного прогона.

## Измерено

### Отрисовка графа и вес фронтенда

Полный отчёт — [vis-network.md](./vis-network.md)
(SF-WEB-76). Коротко:

| Что | Значение |
| --- | ---: |
| `vendor/vis-network.min.js` | 688 911 Б / 161 713 Б gzip |
| весь наш фронтенд, esbuild `--minify` | 216 129 Б / 62 612 Б gzip |
| загрузка лендинга со скриптом vis / без него, 1× CPU | 90 мс / 46 мс |
| то же при троттлинге 4× | 382 мс / 205 мс |
| кадр панорамы с зумом, 600 узлов: библиотека / свой прототип | 3,9 мс / 2,3 мс (медиана) |
| то же, 900 узлов | 5,5 мс / 3,4 мс |

Вывод, ради которого замер и делался: библиотека дорога загрузкой, а не
отрисовкой. При бюджете кадра 16,7 мс она укладывается с запасом даже на
900 узлах — а типичный граф в продукте на порядок меньше
(`GRAPH_DEFAULT_LIMIT = 40`).

## Не измерено

**Ни один сценарий `loadtest/` не прогонялся с записью результата.**
Харнесс написан, workflow настроен, чисел нет.

Что есть: три сценария (`graph_warm`, `path_cold`, `search`), `run-all.sh`,
отдельный workflow. Пороги у сценариев объявлены, но порог — это ожидание,
а не измерение:

| Сценарий | p95 латентности | доля ошибок |
| --- | ---: | ---: |
| `graph_warm` | < 300 мс | < 1% |
| `path_cold` | < 1500 мс | < 2% |
| `search` | < 1000 мс | < 2% |

В `loadtest/README.md` они прямо помечены как **advisory**: выведены из
поведения на моке Genius, а не из боевого трафика, которого у проекта нет.

Чтобы заполнить: поднять стек и прогнать
`bash loadtest/run-all.sh` — он оставит `.txt`-дайджест (итерации,
среднее/p95, доля ошибок, пройден ли порог) и полный `.json` k6 на сценарий.
Числа оттуда — сюда, вместе с датой, железом и тем, тёплый был кэш или
холодный.

Не измерено и стоило бы ещё двух вещей. Доля попаданий в кэш графа за живую
сессию — все утверждения про «из кэша почти мгновенно» держатся на том, что
так выглядит на глаз. И разбивка холодного пути: сколько его секунд уходит в
Genius, а сколько в наш код. Без второй цифры «медленно, потому что сеть»
неотличимо от «медленно, потому что мы», а первое звучит гораздо приятнее и
поэтому само просится в объяснение.
