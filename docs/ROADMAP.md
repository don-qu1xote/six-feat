# SixFeat — Roadmap

Куда движется продукт дальше. Список не исчерпывающий и порядок не
жёсткий — приоритеты уточняются по ходу разработки.

## Производительность и масштаб

- **Быстрее CI** — кэширование сборки между прогонами, чтобы проверка
  изменений не росла линейно с числом сервисов.
- **Единая конфигурация окружений** — по мере роста числа сервисов
  сборка и переменные окружения должны настраиваться одним и тем же
  способом везде, без ручной синхронизации.
- **Партиционирование истории игры** — подготовка базы данных к росту
  объёма игровой активности без просадки производительности.

## Надёжность и безопасность

- **Более широкое end-to-end покрытие** — игровые режимы и сравнение
  артистов пока проверены менее полно, чем основной граф.
- **Дополнительная защита от читов** — систематическое (не только
  ручное) тестирование валидации отправленных цепочек на не совсем
  очевидные обходы.
- **Внутреннее шифрование между сервисами** — дополнительный слой
  защиты на случай компрометации внутренней сети.

## API и интеграции

- **Курсорная пагинация** как общий подход везде, где сейчас отдаются
  большие списки (соседи в графе, таблицы лидеров, публичный API) —
  единообразно вместо разных решений в разных местах.

## Фронтенд

- **Взросление клиентского состояния** — по мере роста числа режимов
  (граф, игра, сравнение) стоит унифицировать управление состоянием,
  чтобы новые фичи не добавляли сложность линейно.
- **Более удобная раскладка на тач-устройствах** — панель с информацией
  об артисте пока рассчитана в первую очередь на десктоп.

## Игра — будущее

- **Импорт из Spotify как источник челленджей** — отдельное подключение
  аккаунта, артисты сопоставляются с той же канонической идентичностью,
  что уже используется для остального графа.

## Рассмотрено и отложено

- **Год/дата релиза на карточке артиста** — решили не делать: цена для
  бэкенда (отдельный источник данных, актуализация) не оправдана ради
  косметического дополнения.
