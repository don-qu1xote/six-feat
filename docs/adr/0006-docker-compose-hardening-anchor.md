# ADR-0006: Общий YAML-якорь хардненинга контейнеров в docker-compose.yml

## Статус

Принято (SF-INF-01, наследник IDEA-29).

## Контекст

Все четыре application-сервиса (`six-feat`, `six-feat-enrichment`,
`six-feat-genius-gateway`, `six-feat-auth`, `six-feat-game`) — стейтлес userver-бинарники:
единственное, во что они пишут на диск в рантайме, это
`/tmp/config_vars.yaml` (см. `docker-entrypoint.sh` каждого сервиса),
всё остальное под `/app`/`/usr/share/six_feat` запечено в образ и не
меняется после сборки. У них нет причины иметь права на запись
куда-либо ещё, лишние Linux capabilities или возможность повышения
привилегий — но повторять один и тот же набор `security_opt`/
`cap_drop`/`read_only` в каждом из четырёх блоков `docker-compose.yml`
означало бы либо копипасту, либо риск, что кто-то забудет применить
хардненинг к новому сервису.

## Решение

Общий YAML-якорь `x-hardening` в `docker-compose.yml`:

```yaml
x-hardening: &hardening
  read_only: true
  tmpfs:
    - /tmp
  cap_drop:
    - ALL
  security_opt:
    - "no-new-privileges:true"
```

Подключается через `<<: *hardening` в блок каждого из четырёх
application-сервисов. Сознательно **не** применяется к `postgres`
(нужна запись в data dir/WAL) и `nginx` (entrypoint пишет
envsubst'нутый конфиг в `/etc/nginx/conf.d` при старте) — у этих двух
контейнеров есть законная причина писать на диск за пределами `/tmp`.

## Последствия

**Плюсы:**
- Новый application-сервис получает хардненинг бесплатно, простой
  строкой `<<: *hardening` — не нужно копировать 8 строк YAML и
  надеяться, что ничего не забыто.
- Изменение политики хардненинга (например, добавить ещё один
  `cap_drop`) — правка в одном месте, а не в четырёх.

**Минусы / цена:**
- Immutable rootfs требует дисциплины: любой новый рантайм-путь записи
  (не только `/tmp`) сломает контейнер тихо (permission denied в логах,
  не при сборке) — обнаруживается только при реальном запуске.
- Якорь — механизм YAML, не Docker Compose-фича `extends`/`profiles`;
  требует, чтобы все нужные сервисы жили в одном `docker-compose.yml`
  файле (нет способа переиспользовать якорь между отдельными compose-
  файлами без дублирования).
