# ADR-0005: Вынести схемы хендлеров/компонентов в YAML и кодогенерировать заголовки

## Статус

Принято (SF-SCH-00, наследник IDEA-54).

## Контекст

Каждый userver-хендлер и компонент обязан реализовать
`GetStaticConfigSchema()`, возвращающий JSON Schema, описывающую его
собственные ключи `static_config.yaml`. Исторически эта схема жила как
инлайновая C++ raw-строка (`R"(...)"`)  прямо в `.cpp`-файле хендлера —
многострочный JSON вперемешку с C++ кодом, без подсветки синтаксиса,
без возможности переиспользовать один и тот же кусок схемы в двух
местах, и без обычных инструментов для валидации YAML/JSON отдельно от
компиляции.

## Решение

Схемы вынесены в отдельные `.yaml`-файлы под `schemas/` (например,
`schemas/components/persistent_store.yaml`,
`schemas/handlers/six-feat/graph_handler.yaml`), и кодогенерируются в
C++ заголовки при конфигурации/сборке через
`six_feat_embed_schema(<schema-path> <const-name> <out-var>)`
(`cmake/EmbedSchema.cmake`):

```
schemas/<schema-path>.yaml
  → generated/schemas/<schema-path>_schema.hpp
    constexpr const char* <const-name> = R"(...)";
```

`GetStaticConfigSchema()` теперь просто `#include`-ит сгенерированный
заголовок и передаёт константу в `yaml_config::MergeSchemas<...>(...)`.

Существенная деталь реализации: заголовок генерируется **и на этапе
`cmake --build`, и eagerly на этапе `cmake -S ... -B build` (configure-
time)** — CI-джоба clang-tidy только конфигурирует проект (чтобы получить
`compile_commands.json`) и никогда не запускает полную сборку; без
eager-генерации на configure-time каждый `.cpp`, инклюдящий
сгенерированный заголовок, не парсился бы clang-tidy'ем вовсе.

## Последствия

**Плюсы:**
- Схема — обычный YAML-файл: подсветка синтаксиса, независимая
  валидация, диффы в code review читаются как диффы конфига, а не как
  диффы C++ строки.
- Один и тот же кусок кодогена переиспользуется для схем хендлеров И
  компонентов одним и тем же макросом.
- clang-tidy CI не ломается на "file not found" для сгенерированных
  заголовков.

**Минусы / цена:**
- Лишний шаг непрямого обращения: чтобы понять, какую схему на самом
  деле использует хендлер, нужно знать путь `schemas/<...>.yaml`, а не
  просто открыть `.cpp`.
- Новый хендлер/компонент требует правки в двух местах:
  `CMakeLists.txt` (вызов `six_feat_embed_schema`) и файл схемы —
  забытый вызов макроса даёт ошибку сборки, а не молчаливо неверное
  поведение, что смягчает риск, но не устраняет лишний шаг.
