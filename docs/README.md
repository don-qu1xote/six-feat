## ★ ТОП 5 ПРИЧИН ЮЗИТЬ ЭТО (ЧЕСТНО)

○ **БЫСТРЫЙ ПОИСК (КОГДА КЭШ ТЁПЛЫЙ)** 
  Кратчайший путь между любыми артистами — из кэша почти сразу, вживую зависит от Genius API и BFS (сеть, а не наш код, тут узкое место)

○ **ГРАФ ПОКАЖЕТ ВСЕ** 
  Интерактивная схема, видишь кто юзался в одной треке, когда, ВСЁ!

○ **СВЕЖИЕ ДАННЫЕ 24/7** 
  Фоновый сканер постоянно качает новое из Genius, ты всегда в теме

○ **КЭШИРОВАНИЕ КАК БОГИ** 
  Повторный поиск срабатывает мгновенно, даже если инет тормозит. И браузер туда же — те же граф/путь/поиск шлют `ETag`, второй запрос с тем же результатом приходит вообще без тела (`304`), лит

○ **ГРАФ УТАЩИШЬ С СОБОЙ** 
  Кнопка "Download JSON" рядом с PNG — весь граф (ноды, рёбра, коллабы) файлом, без скриншотов

○ **ИНТЕРФЕЙС ДЛЯ ЛЕНИВЫХ** 
  Два имени → кнопка → граф. Точка.

## ⚙ КАК ЭТО РАБОТАЕТ (БЕЗ НУДЕЖА)

Не лезем в технические дебри (это всё в `./DEVELOPMENT.md` для гиков-кодеров)

Суть вот такая:

1. Пишешь двух артистов в окно
2. Мы стучим в Genius API (самый **ПОЛНЫЙ** источник по коллабам)
3. **Умное кэширование** запоминает результаты, чтоб было быстрее в следующий раз
4. **Фоновый сканер** постоянно обновляет базу новыми артистами и треками
5. Ты видишь весь граф + кратчайший путь = **ПРОФИТ**

Вся технология спрятана за кулисами — ты просто пользуешь, батон

## ► ЗАПУСК ЗА 5 МИНУТ (БАТОН, ЧЕСТНО)

### Шаг 1: Лезешь на GENIUS как разработчик

Вот сюда → https://genius.com/api-clients

Жмёшь **"Create a new API Client"** и заполняешь форму (напишешь что-нибудь про граф). 
Это макс 2 минуты, фастом

Получаешь:
- **Client ID** (палишь всем, это не секрет, брат)
- **Client Secret** (ХРАНИ КАК ЧЕМОДАН С КЕШЕМ — никому не показывай, ок?!)

### Шаг 2: Копируешь конфиг-шаблон

```bash
cp .env.example .env
```

### Шаг 3: Вставляешь ключи в `.env`

Редактируешь `.env` вот так:

```env
GENIUS_CLIENT_ID=<ТУТ_ВСТАВЛЯЕШЬ_СВОЙ_ID>
GENIUS_CLIENT_SECRET=<ТУТ_ВСТАВЛЯЕШЬ_СВОЙ_SECRET>
```

Остальное система сама сгенерит

### Шаг 4: Дропишь Docker команду

```bash
docker compose up --build
```

Docker будет гружаться, собираться сервер, жди 30-60 сек...

### Шаг 5: Открываешь браузер

```
http://localhost:8080
```

**КРАСОТА!!!** Весь граф перед тобой

## ◆ КАК МЫ НЕ ТОРМОЗИМ (ДАЖЕ НА ПИКАХ)

Юзер спрашивает: "А вы не сдохнете, если 1000 человек одновременно будут искать?"

**Если честно — пока нет, батон.** Пул соединений Postgres и рейт-лимит Genius (по дефолту 8 токенов/сек на форграунд-лейн) — это реальный потолок, 1000 холодных запросов разом встанут в очередь, а не разлетятся молнией. Но вот что реально спасает:

○ **ВСТРОЁННОЕ КЭШИРОВАНИЕ** 
  Каждый найденный артист запоминается в локальной БД. Второй поиск того же артиста — **МОЛНИЯ** срабатывает почти мгновенно

○ **АСИНХРОННАЯ ОБРАБОТКА** 
  Фоновый сканер работает в отдельном потоке, не мешает твоим запросам, всё параллельно

○ **УМНОЕ ОГРАНИЧЕНИЕ ЗАПРОСОВ** 
  Мы уважаем API Genius и не спамим запросами как боты-нубы — и потому тоже не летаем на 10000 запросов в секунду

**1000 одновременно** — это цель НА ПОТОМ, после увеличения пула соединений Postgres и лимитов Genius API. Сейчас всё норм держит обычную нагрузку, кэш решает большинство ситуаций, полный контроль

## ⚙ ДЛЯ ГИКОВ И КОДЕРОВ (ЕСЛИ ХОЧЕШЬ ДОРАБОТАТЬ)

Хочешь кастомить под себя? Не проблема, батон:

```bash
# 1. C++ backend собираешь
cmake -S . -B build && cmake --build build

# 2. JS frontend
cd front && npm install && npm run watch

# 3. Тесты чистишь
pytest tests/ -v
```

Подробно про архитектуру, все переменные, troubleshooting — см. **DEVELOPMENT.md** в репо 
(там полный гайд, не пожалеешь).

Под капотом это не один процесс, а четыре сервиса (`docker compose up` поднимает все разом):
**six-feat** (главный, отдаёт граф/путь/поиск и локально проверяет твою сессию),
**six-feat-enrichment** (фоновый сканер), **six-feat-genius-gateway** (весь трафик в Genius API)
и **six-feat-auth** (весь OAuth-логин: `/auth/login`, `/auth/callback`, `/auth/logout`, `/auth/me`).
Про то, зачем OAuth-флоу выделен отдельно — в DEVELOPMENT.md.
